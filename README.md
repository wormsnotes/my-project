# Portfolio Risk

Учебный проект по курсу «Программная инженерия и C++».

Тема: **«Моделирование стоимости и оценка риска мультивалютного портфеля, включающего денежные средства, акции и облигации, методом Монте-Карло»**.

**Текущая версия:** консольная программа на C++17 для денежных средств в RUB, USD и EUR. Акции и облигации — последующие этапы.

## Что делает программа

1. Генерирует синтетическую историю за год: 252 торговых дня и начальное наблюдение.
2. Хранит цены в долларах: USD за 1 RUB, USD за 1 EUR, USD за 1 USD = 1.
3. Оценивает средние дневные логарифмы доходности, их изменчивость и корреляцию.
4. Использует готовый генератор коррелированных траекторий QuantLib для следующего торгового дня.
5. Выводит текущую и среднюю будущую стоимость, медиану, 95% модельный интервал и вероятность убытка.
6. Отдельно проверяет гипотезу о среднем дневном изменении с помощью центрированного bootstrap.

Все данные искусственные. Они правдоподобны по масштабу, но не являются историческими курсами или прогнозом фактического рынка.

## Сборка в Ubuntu / WSL

Откройте `my-project` в VS Code через Ubuntu. Для этой рабочей папки:

```bash
cd '/mnt/c/Work folder/my-project'
```

Один раз установите зависимости:

```bash
sudo apt-get update
sudo apt-get install -y --no-install-recommends build-essential cmake ninja-build pkg-config libquantlib0-dev libgtest-dev libbenchmark-dev doxygen
```

Соберите проект:

```bash
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build --parallel 2
```

Основная среда — Ubuntu, включая WSL. CMake использует установленные библиотеки; при сборке скачивания зависимостей нет.

## Запуск

Суммы задаются в единицах каждой валюты:

```bash
./build/portfolio-risk --rub 100000 --usd 1000 --eur 500
```

Это портфель из 100000 рублей, 1000 долларов и 500 евро. Пропущенная валюта имеет нулевое количество. Дробная часть вводится через точку. Отрицательные суммы, пустой портфель, NaN и бесконечность запрещены.

Для ввода трёх сумм с клавиатуры:

```bash
./build/portfolio-risk
```

С сохранением истории и явными параметрами:

```bash
./build/portfolio-risk --rub 100000 --usd 1000 --eur 500 --samples 10000 --seed 42 --alpha 0.05 --history-out build/synthetic_fx.csv
```

Родительская папка CSV должна существовать. Справка: `./build/portfolio-risk --help`.

- `--samples`: сценарии прогноза и bootstrap-повторы, от 1 до 1000000.
- `--seed`: seed прогноза, от 1 до 4294967294; по умолчанию 42. Bootstrap использует отдельный поток с seed + 1.
- `--alpha`: уровень значимости строго между 0 и 1; по умолчанию 0.05.
- История всегда генерируется с seed 2026. Изменение числа сценариев или seed прогноза не меняет историю.

При одинаковых аргументах и версиях библиотек расчёт воспроизводим. Другая платформа или версия QuantLib может изменить последние знаки результатов.

## Как читать результат

**Вероятность убытка** — доля сценариев со стоимостью ниже текущей. Изменения в пределах относительной погрешности 1e-12 считаются округлением.

**95% модельный интервал** — квантили 2.5% и 97.5% завтрашней стоимости при фиксированных оценённых параметрах. Он описывает разброс исходов, а не точность оценки среднего. Неопределённость самих параметров в интервал не включена.

**Проверка гипотезы:**

- H0: ожидаемое дневное изменение стоимости портфеля в USD равно нулю.
- H1: ожидаемое дневное изменение стоимости портфеля в USD отрицательно.
- При `p-value < alpha` H0 отвергается в пользу H1.
- Если H0 не отвергается, данных недостаточно для вывода о снижении среднего. Это не доказывает, что стоимость завтра останется прежней.

Проверка использует исторические дневные доходности с текущими весами валют, центрирование к нулю и повторные выборки того же размера. Предполагается независимость и одинаковое распределение этих доходностей. `p-value` не является вероятностью истинности H0 или вероятностью завтрашнего убытка.

Исходные данные содержат 252 дневные доходности. Увеличение числа искусственных сценариев повышает точность численного расчёта и не создаёт новых исторических наблюдений. Синтетическая история демонстрирует метод и не позволяет сделать вывод о реальном рынке.

Математика и допущения: [docs/model.md](docs/model.md).

## Тесты

```bash
ctest --test-dir build --output-on-failure
```

GoogleTest проверяет пересчёт валют, калибровку, воспроизводимость, постоянные курсы, долларовый портфель, аналитическое среднее и вероятность убытка, влияние корреляции, проверку гипотезы и некорректные данные. CTest также проверяет командную строку.

## Бенчмарк

```bash
./build/portfolio_benchmark
```

Google Benchmark измеряет полный расчёт однодневного прогноза для 1000, 10000 и 100000 сценариев: генерацию, переоценку и вычисление квантилей. Подготовка истории и оценка параметров выполняются вне измеряемого цикла. В журнале видны время и число сценариев в секунду.

Для сохранения результата:

```bash
./build/portfolio_benchmark --benchmark_out=build/benchmark.json --benchmark_out_format=json
```

## Документация и CI/CD

```bash
cmake --build build --target docs
```

Локальная HTML-документация: `build/docs/html/index.html`.

Документация в закрытом репозитории: откройте [GitHub Actions](https://github.com/wormsnotes/my-project/actions), выберите успешный запуск и скачайте артефакт `reports-and-documentation`. Распакуйте архив и откройте `docs/html/index.html`.

Адрес подготовленной будущей публикации: [wormsnotes.github.io/my-project](https://wormsnotes.github.io/my-project/). **Сайт пока не опубликован:** текущий тариф GitHub не поддерживает Pages для этого закрытого репозитория. Репозиторий остаётся закрытым по выбору пользователя.

Workflow [`.github/workflows/ci.yml`](.github/workflows/ci.yml) при каждом push и pull request собирает программу, запускает тесты, пример и бенчмарк, генерирует Doxygen. Отчёты, CSV и HTML сохраняются в артефакт `reports-and-documentation`. Скорость также видна в шаге `Run benchmark`.

После успешных проверок в публичном репозитории документация ветки `main` автоматически публикуется через GitHub Pages. При первой публикации workflow включает Pages, если права репозитория позволяют. Сейчас публикация сайта пропускается, но сборка и сохранение HTML в артефакт выполняются. Требования ДЗ о публичном репозитории и опубликованном сайте документации пока не выполнены.
